
## ML Basics
### About Clusters
Training or Infering ML models with heavy weights could be tricky / time consuming when doing in single node cluster. So cluster with multiple nodes so that load is divided within multiple nodes. Ray is one SDK used for setting up this cluster on cloud (Anyscale) or local.

### Product Design Mindset
To built any ML product, it follows the same approach in making any product in general. It could be anything for that matter. But since its related to ML, few things differ here in relation to normal product design. Those points are listed below:

- For the product we envision, we need to identify what user problem it solves and whether ML is really a solution for that problem
- Identify the Product real time end to end flow to understand where the ML component will lye.
- Act as ML engineer and define your role & focus onto how will you improve user experience by your contribution

### Data Ingestion
One of the important part to make sure our model performs really well is Data. We must have all data properly classified/labelled available with manual or automated QA validation. Once data is ready, we can go ahead with Model Training

### Model Metrics
When you identify which model needs to be built, you'll have a general idea on what it actually does. Based on that you've to give metrics based defination to the model on how it should behave. Below are the metrics generally used to define its behaviour:

- Confusion Matrix: Way of classifying outputs generated by the model:
For ex. we've a cancer detection model which classifies whether the patient is diagnosed with cancer or not. 

    - 100 Reports were given as input with 10 aactually having cancer and 90 having normal reports
    - Below is our model's classification
        
        | Actual | Model Output | Count |
        |--------|--------------|-------|
        | Cancer | Cancer | 8 |
        | Cancer | No Cancer | 2 |
        | No Cancer | Cancer | 5 |
        | No Cancer | No Cancer | 95 |

    - Here we define following parameters of Confusion Matrix

        | Term | Meaning | Value |  
        |------|---------|-------|
        | True Positive | Model correctly found cancer | 8 |
        | False Negative | Model missed cancer | 2 |
        | False Positive | Model falsely predicted cancer | 5 |
        | True Negative | Model correctly found No cancer | 95 |

- Precision : Is defined once you've the confusion matrix ready. It is defined as out of the model's Positive outcomes, how often it is correct. Which also means when model says its Cancer is it always correct (maybe its accuracy is low but out of predicted cancer, how many are correct)

    $$precision = \frac{TP}{TP+FP}$$

- Recall : Is basically out of total cases how many are correct in the required outcome (here we'll define how many correct cancer we classified in total ONLY cancer patients)

    $$recall = \frac{TP}{TP+FN}$$

- Accuracy: Out of the Total cases, how many are correct (Both Cancer and Non Cancer)

    $$accuracy = \frac{TP+TN}{TP+FP+TN+FN}$$

- F1 Score: When we select a model we need to identify which could be the best for us High Precision or High Recall. Lets understand what it actually means:

    - Precision = Quality
    → "When I predict positive, am I usually right?"

    - Recall = Coverage
    → "Did I find most of the actual positives?"

    - F1 Score = Balance
    → "Are both quality and coverage good?"

    $$f1 = \frac{2 * precision * recall}{precision + recall}$$

- Rule of Thumb:

    Medical Diagnosis
    → Optimize Recall
    (Missing a disease is expensive)

    Fraud Detection
    → Optimize Recall
    (Missing fraud costs money)

    Search Engines
    → Optimize Precision
    (User wants relevant results)

    Recommendation Systems
    → Optimize Precision
    (Bad recommendations hurt UX)

    Safety-Critical Systems
    → Optimize Recall
    (Missing dangerous events is costly)
